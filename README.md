# ShadowAI — платформа мониторинга неформальной экономики

## О сайте

ShadowAI — веб-приложение для анализа данных компаний и выявления потенциальных экономических рисков. Пользователь может загрузить таблицу или вручную внести сведения о компании, получить демонстрационную оценку риска и изучить результаты в аналитической панели.

Сайт объединяет статистический анализ, проверку сигналов коммерческой активности в социальных сетях и аналитические отчёты с использованием Gemini API. Граф связей помогает изучать связанные компании, а экспорт в PDF, XLSX и CSV позволяет сохранять результаты для дальнейшей работы. Чувствительные поля компаний хранятся в базе SQLite в зашифрованном виде.

Проект предназначен для предварительного анализа: выявленные сигналы требуют проверки специалистом и сами по себе не доказывают нарушения.

## Что умеет MVP

1. Загружает CSV/XLSX/XLS.
2. Обрабатывает данные через Pandas.
3. Считает количество записей, столбцов, пропусков и дубликатов.
4. Анализирует числовые показатели.
5. Выявляет статистические аномалии по правилу ±3 стандартных отклонения.
6. Формирует демонстрационный Risk Score.
7. Показывает результаты в dashboard.
8. Передаёт результаты в Gemini API.
9. Получает автоматический аналитический отчёт.
10. Визуализирует Risk Score через Chart.js.

## Запуск

### Единая оценка риска (company-rules-v2)

Ручной ввод и каждая строка CSV/Excel используют один расчёт из `scoring.py`.
Обязательны `revenue` и `employees`, а при положительной выручке — `tax_percent`
либо `tax_paid`. Для файла с `tax_paid` налоговая доля равна
`tax_paid / revenue × 100`; обе суммы должны относиться к одному периоду и валюте.
Если указаны оба налоговых поля, они должны совпадать (допуск 0,000001 процентного
пункта). Доля округляется до 8 десятичных знаков перед применением правил.
При нулевой выручке доля из платежа не вычисляется, налоговое правило не применяется.
Название обязательно в ручной форме; файл может содержать обезличенные строки.
Телефон сохраняется как текст, включая ведущие нули. Пропущенная выручка не считается нулевой.

Исходные демонстрационные веса:

| Условие | Баллы |
|---|---:|
| Выручка >0, налоговая доля <1% | 30 |
| Выручка >0, налоговая доля от 1% до <3% | 15 |
| Выручка >0, сотрудников 0 | 20 |
| Выручка 0, сотрудников >0 | 20 |
| Выручка 0, активность «высокая» (без учёта регистра) | 12 |
| Выручка ≤1000 и торговые слова в `social_media` | 15 |

Максимальная совместимая сумма — 65. Итог: `round(сумма × 100 / 65)`.
Уровни: 0–29 — низкий, 30–70 — средний, 71–100 — высокий. Это нормированная
демонстрационная шкала, не вероятность нарушения и не откалиброванная модель.
Например, выручка 1000, налог 0,5%, сотрудников 0, активность «высокая» дают
50 исходных баллов и **77/100** при обоих способах ввода.

Пропуски, полные дубликаты и отклонения ±3σ отображаются отдельно как диагностика
таблицы и не повышают баллы компаний. Для многострочного файла общего `risk_score`
нет (`null`): API возвращает `results` с отдельными компаниями, оценками и отчётами,
а `dataset_analysis` содержит диагностику. В интерфейсе выберите строку для просмотра
и скачивания её отчёта. Дубликаты учитываются в диагностике, но строки не удаляются
автоматически. Повторная загрузка по-прежнему создаёт новые записи.

Весь файл проверяется до вызова AI и сохранения. Ошибка строки возвращает HTTP 400
с номером строки; валидный пакет записывается одной транзакцией. AI вызывается для
каждой компании последовательно, поэтому большие пакеты могут обрабатываться долго.

Версия методики сохраняется в БД. Старые записи остаются доступными для экспорта,
но не входят в новую региональную сводку и не окрашиваются по старому баллу в графе.
Для пересчёта загрузите исходные данные повторно: старые агрегированные баллы нельзя
надёжно перевести в индивидуальные оценки без исходных строк.

Проверка: `python -m unittest discover -s tests -v`.

### 1. Создать окружение

```bash
python -m venv venv
```

Mac/Linux:

```bash
source venv/bin/activate
```

Windows:

```bash
venv\Scripts\activate
```

### 2. Установить зависимости

```bash
pip install -r requirements.txt
```

### 3. Настроить Gemini

Скопировать `.env.example` в `.env`:

```bash
cp .env.example .env
```

Затем добавить:

```env
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

Создать ключ шифрования:

```bash
python generate_key.py
```

Добавить полученный ключ в `.env` как `ENCRYPTION_KEY=ваш_ключ`.

### 4. Запустить

```bash
python app.py
```

Открыть:

http://127.0.0.1:5500

## Важное ограничение

MVP выявляет статистические аномалии и потенциальные паттерны. Risk Score не является доказательством нарушения или незаконной деятельности. Для реального государственного применения нужны юридические основания доступа к данным, защита персональных данных, аудит моделей, контроль качества и валидация специалистами.
